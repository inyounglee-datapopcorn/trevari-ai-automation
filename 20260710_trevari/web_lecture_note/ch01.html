• 2. 내가 자동화하고 싶은 '단 하나의 업무' 찾기 책을 읽고 나서, 내 업무 중에서 어떤 일을 가장 먼저 자동화하고 싶어지셨나요? 거창한 시스템이 아니라, 당장 내일의 하루 10분을 덜어낼 수 있는 구체적인 사례를 나눠봅시다. (예: 아침 성과 지표 취합, 메일 초안 작성 등)
• 3. 복붙 업무 해부하기: Trigger, Task, Target 우리가 찾은 그 반복 업무를 자동화의 세 가지 단계로 쪼개어 생각해 볼까요? 언제 시작되고(Trigger), 무엇을 처리하며(Task), 어디로 보내야(Target) 할까요?
• 4. 시간을 되찾는다면, 무엇을 하시겠습니까? "자동화로 하루 10분을 덜어내면, 그 시간이 쌓여 더 중요한 일을 할 수 있습니다." 여러분이 반복 업무를 걷어내고 얻은 그 시간을 어디에, 그리고 어떻게 쓰고 싶으신가요?

🤖 Claude Code & n8n MCP 연동 (심화 실습)

n8n 워크플로우가 수십 개로 늘어나면 관리하기 힘들어집니다. 터미널에서 자연어(말) 한마디로 n8n을 제어하고 자동화할 수 있도록 Claude Code와 n8n MCP를 연결해 봅니다.

1

Claude Code 설치: 터미널을 열고 npm install -g @anthropic-ai/claude-code 명령어로 설치 후 claude를 실행하여 로그인합니다.

2

n8n API 키 발급: n8n 워크스페이스 좌측 하단의 Settings > n8n API 메뉴에서 새로운 API 키를 생성하고 안전하게 복사합니다.

3

MCP 서버 연결: 터미널에 claude mcp add n8n -- npx -y n8n-mcp-server를 입력하고, 안내에 따라 n8n 서버 URL(예: https://...)과 복사한 API 키를 입력합니다.

4

첫 자연어 명령 성공하기: 연동이 끝났다면, "현재 n8n에 있는 워크플로우 목록 보여줘" 라고 명령하여 성공적으로 n8n 데이터를 읽어오는지 확인합니다.

💡 MCP 연동이 왜 중요한가요?
단순히 남이 만든 워크플로우를 복붙하는 것을 넘어, AI가 내 n8n 환경을 이해하고 스스로 워크플로우를 생성, 수정, 에러 분석까지 해주는 '자동화 관리자'를 고용하는 것과 같습니다.

1회차 모임 기록

📝 7월 10일, 우리는 이런 이야기를 나눴습니다

첫 모임에서는 각자의 반복 업무와 참여 이유를 나누고, AI에게 일을 맡기기 위해 업무를 구조화하는 법을 익혔습니다. n8n을 직접 살펴보며 간단한 자동화를 실행했고, 자동화로 되찾은 시간을 어디에 쓸지도 함께 이야기했습니다.

1. 멤버들이 자동화하고 싶었던 일

  • 정확성이 중요한 업무: 급여·회계처럼 휴먼 에러가 큰 영향을 주는 업무의 검수와 반복 처리
  • 문서와 커뮤니케이션: 신청서·PDF 필수 항목 확인, 누락 안내, 이메일 초안 작성과 후속 전달
  • 데이터 정리와 보고: ERP·엑셀 데이터 추출, 피벗·PPT 보고서 작성, 여러 출처의 정보 취합
  • 사업 운영: 쇼핑몰 상품 등록, 마케팅, 신청·입금·취소 관리 등 혼자 처리하는 자잘한 운영 업무
  • 정보 모니터링: 해외 펀드 관련 뉴스·제도 변화 수집, 계약서 검토, 운용 보고서 초안 작성
  • 조직의 AX: 아날로그적이고 노동집약적인 제조 현장에 AI와 자동화를 적용하는 방법 탐색

2. 가장 중요했던 공통 언어

AI 자동화의 출발점은 도구의 모든 기능을 외우는 것이 아니라, 내가 하는 일을 다른 사람에게 설명하듯 말로 풀어내는 것입니다. 익숙한 업무일수록 암묵지가 많기 때문에, 처음에는 마이크를 켜고 실제 업무 과정을 편하게 설명한 뒤 AI에게 구조화를 부탁하는 방법도 활용할 수 있습니다.

Trigger
언제, 무엇을 계기로 시작할까?
Task
어떤 정보를 어떻게 처리할까?
Target
결과를 어디에 남기거나 보낼까?

처음부터 완벽한 워크플로우를 만들기보다 큰 흐름을 먼저 그리고, n8n의 스티키 노트와 노드를 블록처럼 하나씩 연결해 구체화하는 방식으로 접근했습니다.

3. 함께 살펴본 사례와 실습

  • PDF 신청서의 이름·주소·서명·동의 여부를 검수하고, 정상·누락·담당자 확인 필요 상태로 분기하는 흐름
  • 메일이 오면 일정과 필수 조건을 확인해 답장 초안을 준비하는 반자동 업무 위임 사례
  • 공유오피스 출입 기록을 API로 가져와 슬랙에 자동으로 출퇴근 기록을 남기는 사례
  • 매일 나무위키 인기 키워드를 가져와 이미지를 생성하고 슬랙 프로필을 바꾸는 재미 중심의 자동화
  • 브라우저·컴퓨터 사용 기능으로 웹사이트 버튼을 누르거나 카카오톡 메시지를 보내는 에이전트 시연
  • 현장 실습: 1분마다 AI가 만든 명언을 Gmail로 보내는 n8n 워크플로우를 실행하고, 실행 이력과 게시(Publish) 개념 확인
  • 심화 시연: Claude Code에서 “매일 아침 9시 헤드라인을 요약해 이메일로 보내기”라고 자연어로 요청해 n8n 워크플로우를 만드는 과정 확인

4. 도구를 고를 때 기억할 기준

  • n8n: 규칙과 단계가 명확하고, 중간 흐름을 눈으로 확인하거나 세밀하게 수정해야 할 때 유리합니다.
  • Claude Code·Codex 같은 에이전트: 자연어로 목표를 전달하고 여러 도구를 연결해 일을 위임할 때 유리합니다.
  • 브라우저·컴퓨터 사용: API가 없는 서비스도 화면을 직접 조작하는 방식으로 시도할 수 있지만, 속도와 안정성을 검토해야 합니다.
  • 보안: 회사 메일·ERP·고객 정보는 조직의 허용과 접근 권한이 먼저입니다. AI 연결을 위해 외부 권한을 열 때는 정보의 민감도를 반드시 확인해야 합니다.
  • 비용 대비 효과: 5분짜리 일을 자동화하느라 몇 주를 쓰지 않도록, 개발 시간·구독료·서버 비용보다 절약되는 시간과 가치가 큰지 먼저 계산합니다.

5. 자동화로 되찾은 10분을 어디에 쓸까?

자동화의 목적을 “더 많은 일을 하기 위해서”로만 두지 않았습니다. 멤버들은 잠을 더 자기, 운동과 산책하기, 생각하고 싶은 것에 집중하기, 나를 돌아보기, 가족과 주변 사람에게 시간 쓰기, 새로운 사업을 구상하기 등을 이야기했습니다.

1회차의 결론: 작은 반복 업무 하나를 덜어내는 데서 시작하되, 그렇게 되찾은 시간을 무엇을 위해 쓸지까지 함께 설계해야 합니다.

다음 모임 전까지

  1. 공용 n8n 워크스페이스에 접속해 빈 워크플로우를 하나 만들어보기
  2. 내 반복 업무 하나를 Trigger → Task → Target으로 나누어 스티키 노트에 적기
  3. 책이나 제공된 예제를 따라 간단한 노드를 직접 연결하고 한 번 실행해보기
  4. 막힌 지점과 궁금한 점을 기록해 톡방에 공유하거나 2회차에 노트북과 함께 가져오기
  5. 2회차 읽을거리 『가짜 노동』을 읽으며 내 일의 ‘진짜 노동’과 ‘가짜 노동’을 구분해보기

워크플로우 JSON 다운로드 ↓

n8n에 워크플로우 추가하는 방법

  1. 파일 다운로드: 위 버튼을 눌러 quote-email-workflow.json을 저장합니다.
  2. n8n 접속: 공용 워크스페이스 또는 개인 n8n에 로그인한 뒤 Workflows 화면으로 이동합니다.
  3. JSON 가져오기: 우측 상단의 ⋯ 메뉴 → Import from File을 선택하고 내려받은 JSON 파일을 엽니다. 버전에 따라 새 워크플로우 화면의 우측 상단 메뉴에 표시될 수 있습니다.
  4. OpenAI 연결: OpenAI Chat Model 노드를 열고 Credential to connect with에서 내 OpenAI API 자격 증명을 선택하거나 새로 만듭니다.
  5. Gmail 연결: Send a message 노드를 열고 내 Gmail 계정을 연결합니다. Send To의 안내 문구를 실제로 받을 이메일 주소로 반드시 변경합니다.
  6. 테스트 실행: 먼저 Execute Workflow를 눌러 한 번 실행하고, 모든 노드에 초록색 체크가 표시되는지와 이메일이 실제로 도착했는지 확인합니다.
  7. 주기 조정 후 게시: 예제는 실습을 위해 1분 간격입니다. 테스트가 끝나면 Schedule Trigger를 하루 1회 등 원하는 주기로 바꾼 다음 Publish 또는 Active를 켭니다.
⚠️ 꼭 확인하세요. 가져온 파일에는 클럽장의 API 키나 Gmail 로그인 정보가 포함되어 있지 않습니다. 각자 자신의 계정을 연결해야 하며, 1분 주기로 활성화하면 메일이 계속 발송되고 OpenAI API 비용도 발생할 수 있으니 테스트 후 주기를 바꾸거나 워크플로우를 비활성화하세요.
